# Техническое задание (ТЗ)
# АИС «Салон-парикмахерская HAIR SALON»

## 1. Описание проекта

### 1.1. Назначение

**АИС «Салон-парикмахерская HAIR SALON»** — веб-приложение для автоматизации деятельности салона-парикмахерской среднего размера (3–5 мастеров).

Система обеспечивает:
- онлайн-запись клиентов на услуги;
- управление расписанием мастеров и слотами времени;
- ведение каталога услуг и мастеров;
- личные кабинеты для трёх ролей (клиент, мастер, администратор);
- формирование отчётов и архивацию данных.

### 1.2. Проблема, которую решает система

| Проблема                  | Решение                             |
|---------------------------|-------------------------------------|
| Запись только по телефону | Онлайн-запись 24/7                  |
| Двойные бронирования      | Транзакционная блокировка слотов    |
| Данные в блокнотах        | Единая база MySQL                   |
| Нет аналитики             | Отчёты по выручке и загрузке        |
| Нет истории клиента       | Личный кабинет с историей посещений |

### 1.3. Ценность продукта

**Клиент:** экономия времени, самозапись, прозрачный прайс-лист, история визитов.
**Мастер:** понятное расписание, быстрая смена статусов.
**Администратор:** единая база, отчёты, контроль загрузки.

## 5. Описание обработки ошибок

### 5.1. Единый формат ошибок API

Все ошибки возвращаются в формате:

```json
{
  "error": "код_ошибки",
  "message": "Человекочитаемое сообщение",
  "details": { "field": "extra info" }
}
```

### 5.2. HTTP-коды

| Код | Класс ошибки    | Применение                         |
|-----|-----------------|------------------------------------|
| 200 | OK              | Успешный запрос                    |
| 201 | Created         | Создание сущности                  |
| 204 | No Content      | Успешное удаление                  |
| 400 | ValidationError | Ошибка валидации                   |
| 401 | AuthError       | Не авторизован                     |
| 403 | ForbiddenError  | Недостаточно прав                  |
| 404 | NotFoundError   | Ресурс не найден                   |
| 409 | ConflictError   |  Конфликт (дубликат, занятый слот) |
| 500 | InternalError   | Внутренняя ошибка сервера          |

### 5.3. Сценарии обработки

#### E-1. Ошибки валидации (400)

**Сервер:**
```json
{
  "error": "validation_error",
  "message": "Ошибка валидации",
  "details": {
    "errors": [
      { "field": "email", "message": "Некорректный email" },
      { "field": "password", "message": "Пароль < 8 символов" }
    ]
  }
}
```

**Клиент:** подсветка полей + inline-сообщения.

#### E-2. Неавторизованный доступ (401)

**Сервер:** `AuthError('Требуется аутентификация')`.
**Клиент (API):** показывает toast.
**Клиент (HTML):** редирект на `/auth/login` с сохранением `returnTo`.

#### E-3. Недостаточно прав (403)

**Сервер:** `ForbiddenError('Доступ запрещён')`; для HTML-запросов сервер
рендерит `src/views/errors/403.pug` **на текущем URL** — отдельного маршрута
`GET /errors/403` в приложении нет.
**Клиент (API):** JSON `{ "error": "forbidden", "message": ... }`.
**Клиент (HTML):** страница 403 отображается без редиректа.

#### E-4. Ресурс не найден (404)

**Сервер:** `NotFoundError('Ресурс не найден')`.
**Клиент (API):** JSON с ошибкой.
**Клиент (HTML):** страница `errors/404.pug`.

#### E-5. Конфликт данных (409)

**Примеры:**
- Дубликат login/email/phone.
- Занятый слот.
- Недопустимый переход статуса (`invalid_transition`).
- Удаление категории с услугами.

**Клиент:** сообщение «Логин, email или телефон уже заняты» / «Слот уже занят».

#### E-6. Внутренние ошибки (500)

**Сервер:** логирует `err.stack` через `console.error`.
**Клиент:** показывает generic-сообщение «Что-то пошло не так. Попробуйте позже», не раскрывая стек.

#### E-7. Пустые данные

**Клиент:** плейсхолдер с иконкой + CTA-кнопка:
```
📅 У вас пока нет записей
[ Записаться онлайн ]
```
#### E-8. Сетевые ошибки (клиент)

**Клиент:** toast-уведомление «Не удалось подключиться. Проверьте интернет».
**Кнопка:** разблокируется для повторной попытки.

### 8.3. Acceptance Criteria (Given-When-Then)

**AC-1. Регистрация клиента**
- **Given** открыта форма `/auth/register`
- **When** введены валидные ФИО, login, email, phone, password
- **Then** ответ `201`, создана сессия, редирект на `/account`

**AC-2. Онлайн-запись (happy path)**
- **Given** клиент авторизован, выбрана услуга и мастер
- **When** выбраны дата и свободный слот, запись подтверждена
- **Then** запись в статусе `Created`, слот переведён в `busy`, запись видна в `/account`

**AC-3. Конфликт слота**
- **Given** выбранный слот занят параллельной записью
- **When** клиент подтверждает бронирование
- **Then** `409` `slot_unavailable`, транзакция откатилась, никакие слоты не изменены

**AC-4. Отмена записи клиентом**
- **Given** у клиента есть активная запись
- **When** он нажимает «Отменить»
- **Then** статус `Cancelled`, слоты освобождены (`free`), запись доступна в истории

**AC-5. Смена статуса мастером**
- **Given** запись в статусе `Confirmed`
- **When** мастер нажимает «Начать», затем «Завершить» с фактической ценой
- **Then** статусы `InService` → `Completed`, `actual_price` сохранена, переход разрешён матрицей

**AC-6. Недопустимый переход статуса**
- **Given** запись в терминальном статусе `Archived`
- **When** любой запрос на переход статуса
- **Then** `409` `invalid_transition`, статус не изменился

**AC-7. Отчёт и экспорт CSV**
- **Given** заданы тип отчёта и период
- **When** администратор формирует отчёт (`POST /api/admin/reports`)
- **Then** `201`, итоги считаются только по `Completed`; при экспорте — CSV в UTF-8 с BOM, кавычки/запятые по RFC 4180

**AC-8. Архивация периода**
- **Given** период не пересекается с существующими архивами
- **When** `POST /api/admin/archives` с `date_from`, `date_to`
- **Then** создан архив, снимок `Completed`/`Cancelled` записей в `archived_appointments`, исходные записи переведены в `Archived`; при пересечении — `409` `archive_period_overlap`

**AC-9. Разграничение доступа**
- **Given** анонимный пользователь или роль `client`
- **When** запрос к страницам `/admin` или API `/api/admin/*`
- **Then** HTML — редирект на `/auth/login` с сохранением `returnTo`; API — `401` (без сессии) или `403` (чужая роль) в формате `{error, message}`
